Claude Code / Codex Autonomy Ladder

The shift is from "ask and copy-paste" to "write a spec, delegate, verify." Climb one rung at a time.

Chat (baseline)

Ask questions, paste code, copy answers. Useful, but the tool never touches your files or runs anything.

Read-and-explain in your repo

  • Open a project and ask it to map the codebase or explain a script.
  • Use plan mode: it proposes edits, you approve.
  • Exercise: have it explain every command before you allow it.

Delegate one bounded task

  • Give a written spec plus an acceptance test.
  • Review the diff like a colleague's pull request.
  • Exercise: fix a bug from a failing test.

Teach it your project

  • Write CLAUDE.md / AGENTS.md.
  • Create a reusable skill for a repeated procedure.
  • Add custom slash commands and hooks.

Run several workers

  • Parallel sessions in separate git worktrees.
  • Subagents for research or review so your main context stays clean.

Automate without you

  • Headless mode inside scripts, cron, or GitHub Actions.
  • Agent produces a report or PR on a schedule, pauses for approval on anything external.
Habits that unlock the most power

Spec before code

Goal, inputs, outputs, constraints, how to verify — in 10 lines, before you ask for anything.

Give it a way to check itself

Tests, linters, sample inputs. Agents improve dramatically when they can run a check and iterate.

Small commits, always

Commit before each delegated task so a bad result is one command from undone.

Manage context deliberately

Clear between unrelated tasks, keep instruction files short.

Use both tools, compare

Same spec into Claude Code and Codex — diff the results to learn each tool's strengths fast.

Keep a failure log

Where it went wrong, and what instruction would've prevented it. Becomes your best CLAUDE.md.

Concepts & Cheatsheet

No derivations, no model-training theory — just enough to reason about systems and talk to an interviewer.

Token efficiency

What a token is

A chunk of ~3-4 characters. Code and non-English text often cost more per idea. Output tokens usually cost more than input.

Spend fewer

  • Send only what the task needs; retrieve, don't paste whole docs.
  • Ask for structured, capped output.
  • Route easy steps to a small model.

Reuse more

  • Stable content first in the prompt (caching).
  • Batch non-urgent jobs.
  • Cache repeated identical calls yourself.

Waste to avoid

  • Re-sending giant context with no caching.
  • Agent loops with no stopping condition.
  • Raw tool output dumped into context.

Just enough math intuition

Next-token prediction

The model outputs a probability for every possible next token, picks one, repeats.

Embeddings

Text as coordinates so similar meanings sit close together. Cosine similarity measures "how close."

Attention

For each token, the model weighs which earlier tokens matter most — a weighted lookup.

Why hallucination happens

Trained for plausible text, not verified truth. Grounding, citations, and evals are the mitigation.

What is a skill? (Claude Code / Codex)

What it is

A packaged, reusable set of instructions (and optionally scripts) the agent loads on demand instead of you re-explaining a procedure every session.

When to create one

Any time you catch yourself repeating the same instructions across sessions — a report format, a review checklist, a data-cleaning convention.

How to create one

Write a SKILL.md: what it's for, when to trigger, step-by-step instructions, any helper scripts. Keep it scoped to one procedure.

How to use one

The agent can auto-load it when relevant, or you invoke it by name. Test that it actually triggers on the cases you intended.
